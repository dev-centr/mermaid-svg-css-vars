= mermaid-svg-css-vars

Post-process Mermaid SVG: theme colors to CSS vars with fallbacks + webCompatibility normalization.

link:https://github.com/dev-centr/mermaid-svg-css-vars/issues[Report Bug] ·
link:https://github.com/dev-centr/mermaid-svg-css-vars/issues[Request Feature]
endif::[]

== About The Project

Mermaid adapter that post-processes rendered SVG for responsive web embedding and can apply the generator-neutral https://github.com/dev-centr/themed-svg[Themed SVG] standard.

Package: `@dev-centr/mermaid-svg-css-vars`

Mermaid derives theme colors with *khroma* from *concrete* color values, so CSS custom properties cannot be used as renderer inputs. The legacy API rewrites emitted colors to `var(--mermaid-primaryColor, #resolvedFallback)`. Those variables can be controlled when the SVG is inline; a page's CSS does not cross into an SVG loaded through `<img>`.

== Usage

[source,ts]
----
import {
  rewriteMermaidSvgCssVars,
  normalizeMermaidSvgForWeb,
  prepareMermaidSvgForWeb,
} from '@dev-centr/mermaid-svg-css-vars';

const ready = prepareMermaidSvgForWeb(svg, {
  themeVariables,
  cssVariables: true,
  webCompatibility: true,
  prefix: '--mermaid-',
});
----

=== Themed SVG adapter

New integrations should use an explicit Themed SVG manifest. Mermaid is the source renderer; the independent standard owns semantic tokens, bundled light/dark presets, fixed output, and host-boundary behavior.

[source,ts]
----
import { prepareThemedMermaidSvg } from '@dev-centr/mermaid-svg-css-vars';

const result = prepareThemedMermaidSvg(renderedMermaidSvg, manifest, {
  mode: 'host',
  lightPalette: siteLightPalette,
  darkPalette: siteDarkPalette,
});
----

To produce the portable fallback and progressive host artifact atomically at
the transform boundary, call the dual-output API. It returns neither SVG when
either transform reports an error:

[source,ts]
----
import {
  prepareThemedMermaidSvgDualOutput,
} from '@dev-centr/mermaid-svg-css-vars';

const { standaloneSvg, hostSvg, diagnostics } =
  prepareThemedMermaidSvgDualOutput(renderedMermaidSvg, manifest, {
    lightPalette: siteLightPalette,
    darkPalette: siteDarkPalette,
  });
----

The adapter consumes the published `@dev-centr/themed-svg` package.

=== CLI

The recommended CLI flow uses one Themed SVG manifest. Render Mermaid once,
then use `--dual-output` to write the portable adaptive artifact and its host
sibling:

[source,bash]
----
mmdc -i diagram.mmd -o diagram.raw.svg -c mermaid-config.json
mermaid-svg-css-vars --manifest diagram.theme.json \
  --dual-output diagram.raw.svg

# CI: exit 3 and report each stale or missing committed artifact
mermaid-svg-css-vars --manifest diagram.theme.json \
  --dual-output --check diagram.raw.svg
----

The default names are `diagram.svg` for `standalone-adaptive` output and
`diagram.host.svg` for runtime output. Use `--output` and `--host-output` to
override them. The default `host` mode remains available when only one output
is needed. Keep the Mermaid renderer's intermediate file named `*.raw.svg` so
the committed pair has the stable `name.svg` and `name.host.svg` convention.

Choose another generic output mode when the embedding boundary requires it:

[source,bash]
----
# Self-contained light/dark SVG for an external <img>
mermaid-svg-css-vars --manifest diagram.theme.json \
  --mode standalone-adaptive diagram.svg -o diagram.adaptive.svg

# Concrete light and dark files; names default to diagram.light.svg
# and diagram.dark.svg
mermaid-svg-css-vars --manifest diagram.theme.json \
  --mode paired-fixed diagram.svg
----

Generic manifest options also accept `--preset`, `--palette`,
`--light-palette`, `--dark-palette`, `--host-output`, `--light-output`, and
`--dark-output`. Transform diagnostics are written to stderr; an error
diagnostic exits with status 2 and emits no SVG. A dual freshness mismatch
exits with status 3.

The older `--theme-vars`, `--prefix`, `--no-css-variables`, and web
normalization flags remain available only as a compatibility route:

[source,bash]
----
mermaid-svg-css-vars --theme-vars theme.json --prefix --mermaid- \
  diagram.svg -o diagram.legacy.svg
----

Manifest and legacy options cannot be mixed.

=== Embedding boundary

Host CSS variables work only when the SVG is inline in the page. An SVG loaded through `<img>` is an isolated document and uses its concrete fallback values.

The recommended `<themed-svg>` runtime path consumes `host` output and controls
its namespaced variables. For a plain external image, use the adapter's
self-contained `standalone-adaptive` output or paired fixed assets. Legacy
inline output can still follow the site's manual theme state:

[source,css]
----
:root {
  --mermaid-primaryColor: #ECECFF;
  --mermaid-primaryTextColor: #333;
}
[data-theme="dark"] {
  --mermaid-primaryColor: #2a2a4a;
  --mermaid-primaryTextColor: #eee;
}
----
